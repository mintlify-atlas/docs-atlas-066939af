---

Guardián Centinela persists every fraud decision to the `predicciones` table the moment it is made. These two endpoints expose that log — one for browsing the most recent decisions across all transactions, and one for replaying the complete decision history of a single transaction. Both are primarily used for auditing, compliance reporting, and debugging.

**Base URL (via gateway):** `http://localhost:8080/api/dominio`

---

## GET /predicciones

Returns the most recent fraud decisions across all transactions, ordered from newest to oldest.

### Query parameters

<ParamField query="limit" type="integer">
  Maximum number of records to return. Accepted range: `1`–`200`. Defaults to `20`.
</ParamField>

### Response — 200 OK

An array of decision summary objects ordered by `prediccion_id DESC` (most recent first).

<ResponseField name="prediccion_id" type="integer">
  Auto-incremented primary key that establishes the chronological order of decisions.
</ResponseField>

<ResponseField name="transaccion_id" type="string">
  The transaction identifier associated with this decision.
</ResponseField>

<ResponseField name="usuario_id" type="string">
  The user who initiated the transaction.
</ResponseField>

<ResponseField name="decision" type="string">
  The fraud decision outcome: `"aprobar"`, `"revisar"`, or `"bloquear"`.
</ResponseField>

<ResponseField name="origen" type="string">
  Which system produced the decision: `"modelo"`, `"regla_dura"`, or `"reserva"`.
</ResponseField>

<ResponseField name="probabilidad" type="number | null">
  Calibrated fraud probability `[0, 1]`, or `null` when the fallback engine was used.
</ResponseField>

<ResponseField name="version_modelo" type="string | null">
  Model version that scored the transaction, or `null` for fallback decisions.
</ResponseField>

<ResponseField name="version_umbrales" type="string | null">
  Threshold configuration version, or `null` for fallback decisions.
</ResponseField>

<ResponseField name="latencia_ms" type="number">
  Total processing time for the original request, in milliseconds.
</ResponseField>

<ResponseField name="creado_utc" type="string">
  ISO 8601 UTC timestamp of when the decision was persisted.
</ResponseField>

### Example

curl -s "http://localhost:8080/api/dominio/predicciones?limit=3"

## GET /predicciones/\{transaccion\_id\}

Returns **all** recorded decisions for a specific transaction. Because the same `transaccion_id` can be submitted to `POST /evaluar` more than once — for example, when a retried payment is re-evaluated — this endpoint returns the full ordered history so you can see how model versions or threshold changes affected the outcome over time.

### Path parameters

<ParamField path="transaccion_id" type="string" required>
  The transaction identifier to replay. Must match a value in the `predicciones` table exactly.
</ParamField>

### Response — 200 OK

An array of full `predicciones` records (`SELECT * FROM predicciones`) ordered by `prediccion_id ASC` (earliest decision first). Each record includes all columns: `prediccion_id`, `transaccion_id`, `usuario_id`, `dispositivo_id`, `entrada` (the complete enriched payload sent to the IA), `probabilidad`, `decision`, `origen`, `razones`, `version_modelo`, `version_umbrales`, `latencia_ms`, and `creado_utc`.

### Error responses

| Status | Meaning |
|--------|---------|
| `404 Not Found` | No decisions exist for the given `transaccion_id`. Response body: `{"detail": "Sin decisiones registradas para esa transacción"}` |

<Note>
  This endpoint implements **RF7 — replay capability**. The `entrada` column in each row stores the complete enriched payload that was actually sent to the IA service (including resolved user and device profiles and blocklist flags). Combined with `version_modelo` and `version_umbrales`, you can reconstruct exactly what data, what model, and what thresholds produced any given decision — a full audit trail from input to outcome.
</Note>
